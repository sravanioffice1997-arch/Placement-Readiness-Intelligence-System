# Placement Readiness Intelligence System (PRIS)

AI-powered Resume and Job Description Based Placement Readiness Analyzer

## Overview

PRIS helps students answer one question: **"Am I ready to apply for this job, and what's stopping me?"**

A student uploads their resume and pastes a job description. The system reads both, extracts skills contextually using an LLM (no fixed keyword list), compares them, predicts a **Placement Readiness Score out of 100** using a trained machine learning model, and generates a personalized coaching report — strengths, gaps, a 7-day plan, and a 30-day plan — downloadable as a PDF.

**Domain:** EdTech / Placement Analytics / Resume Intelligence / Career Readiness

## How It Works

The system is built from two engines working together:

- **Engine 1 — Text Understanding (LLM-based, via Groq API):** Reads the resume and JD contextually to extract skills, projects, certifications, and requirements. No fixed skill dictionary — works for any job domain.
- **Engine 2 — ML Model:** Converts the LLM's output into 11 numeric features (skill match %, missing skills count, project relevance, etc.) and feeds them into a trained classifier that outputs the readiness label and score.

Only the final placement readiness score is produced by the ML model, as specified in the project brief. All resume/JD analysis, skill gap detection, and feedback generation are LLM-powered.

## Features

- Resume PDF ingestion and text extraction
- Contextual skill extraction (resume + JD) — no fixed skill list
- JD-anchored skill gap analysis: matched skills, missing skills, critical missing skills
- Required vs. optional ("good to have") skill classification, matching the JD's own structure
- ML-based placement readiness score (0–100) with a 4-class label: Highly Ready / Moderately Ready / Needs Improvement / Not Ready Yet
- Personalized LLM-generated feedback: strengths, gaps, 7-day plan, 30-day plan, resume suggestions, interview tips
- Streamlit dashboard with upload, analysis, and results display
- Downloadable PDF report

## Tech Stack

- **LLM:** Groq API (Llama 3.3 70B)
- **ML:** scikit-learn (Logistic Regression / Decision Tree / Random Forest / Gradient Boosting — best model auto-selected)
- **PDF processing:** PyPDF2 (reading), fpdf2 (report generation)
- **Dashboard:** Streamlit
- **Data:** pandas, numpy

## Setup & Installation

1. Clone this repository and navigate into the project folder.

2. Install dependencies:
   ```bash
   python -m pip install -r requirements.txt
   ```

3. Add your Groq API key. Open `app.py` and replace:
   ```python
   GROQ_API_KEY = "PASTE_YOUR_GROQ_API_KEY_HERE"
   ```
   Get a free API key at [console.groq.com](https://console.groq.com).

4. Ensure `readiness_model.pkl`, `label_encoder.pkl`, and `feature_columns.pkl` are present in the same folder as `app.py`. These are generated by training the model (see **Model Training** below) or can be downloaded from this repo if already committed.

5. Run the app:
   ```bash
   python -m streamlit run app.py
   ```
   The app opens automatically at `http://localhost:8501`.

## Model Training (Reproducing the ML Model)

The ML model is trained on a synthetic dataset, since no public dataset of labeled real resume-readiness pairs exists.

1. **Generate the synthetic dataset** (`step1_dataset_generator.py`): creates ~10,000 synthetic candidate feature-vectors across 4 readiness classes, using per-class ranges, added noise, and ~6% label noise to simulate real-world ambiguity. Produces `placement_readiness_dataset.csv`.

2. **Train and compare models** (`step2_train_model.py`): trains Logistic Regression, Decision Tree, Random Forest, and Gradient Boosting classifiers, evaluates each, and saves the best-performing model along with the label encoder and feature column order.

Both scripts are included in this repo and are designed to run in Google Colab, though they work in any standard Python environment with the dependencies installed.

## The 11 ML Features

| Feature | Description |
|---|---|
| `skill_match_percentage` | % of JD-required skills found in the resume |
| `critical_skill_match_percentage` | % of critical required skills found |
| `missing_skills_count` | Count of required skills not found |
| `critical_missing_skills_count` | Count of critical required skills not found |
| `optional_skill_match_percentage` | % of "good to have" skills found (does not gate top readiness tier) |
| `project_relevance_score` | How well resume projects support the matched skills |
| `certification_relevance_score` | Presence of relevant certifications |
| `internship_relevance_score` | Presence of internship experience |
| `resume_completeness_score` | LLM-assessed completeness of the resume |
| `keyword_match_score` | Required-skill keyword match strength |
| `role_category_match_score` | Alignment between resume and the JD's role category |

## Design Notes

- **JD-anchored matching:** all match percentages are calculated relative to what the JD requires, not the resume's total skill count — so extra unrelated skills on a resume don't inflate the score, and a candidate matching all required skills scores well regardless of how many additional skills they list.
- **Required vs. optional skills:** the system respects the JD's own structure (e.g. "Required Skills" vs. "Good to Have" sections) rather than treating all listed skills as equally mandatory. Missing optional skills are shown to the student as a minor improvement area but do not disqualify an otherwise strong match.
- **Scope:** PRIS is designed for students and freshers evaluating placement readiness, so the feature set focuses on skills, projects, and certifications rather than years of professional work experience.
- **Score cap:** the readiness score is capped at 90/100 to avoid implying a resume is a "perfect" match, even at maximum model confidence.
